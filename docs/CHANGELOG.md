# 版本演进说明

## v0.7

### 版本定位

`v0.7` 标志着项目从“可运行的业务原型”进入“功能已成型、工程化仍在持续完善”的阶段。

这一版不再只是补功能点，而是围绕三件事做统一收束：

- 配置来源统一：开发、测试、Jenkins 都围绕 `.env` 体系工作
- 结构分层更清晰：路由、服务、仓储、运行时、测试辅助职责边界更稳定
- 测试与集成更稳：减少状态污染、降低重复开销、让回归结果更可复现

### 本版核心变化

#### 1. 配置与集成链路统一

- 补齐 `.env.example`、`.env.dev`、`.env.test` 的职责划分
- Jenkins 流水线改为基于 `.env.test.example` 和环境变量生成 `.env`，再统一读取 `.env`
- 开发环境、测试环境、CI 环境的配置入口保持一致
- 依赖文件拆分为 `requirements.txt` 和 `requirements-dev.txt`

#### 2. 认证与权限链路稳定化

- 登录、注册、密码修改、会话管理继续沿用统一认证服务
- 登录失败限流按“来源 + 用户名”维度处理
- `viewer / admin` 权限边界在路由与测试层保持一致
- 管理员能力覆盖用户管理、角色调整、ROI 更新与测试账号清理

#### 3. 运行时与缓存链路收敛

- `MockPeopleCounter` 与 `PeopleCounter` 的状态刷新、事件投递和日统计同步接口进一步统一
- Redis 状态缓存、事件缓存与 MySQL 落库逻辑边界更清楚
- 事件队列与消费者的消息结构显式化
- 密码哈希与校验逻辑增加损坏输入保护

#### 4. 测试工程能力强化

- 测试工具层补齐 `APIClient`、Redis/MySQL helper、环境加载和报告辅助
- 修复认证限流测试的偶发失败，改为局部唯一状态与精确清理
- 修复管理员 ROI 测试对默认配置的长期污染
- 测试用户创建后增加回收逻辑，降低数据库脏数据积累
- `mock / real` 模式探测改为会话级缓存，减少重复 HTTP 开销
- Allure 附件改为失败时再落盘，降低成功用例的 I/O 负担

#### 5. 文档与仓库可迁移性提升

- README 补充环境文件约定与安装说明
- Jenkins、依赖文件、示例配置的约定保持一致
- 示例模板与本地真实配置分层，减少仓库本地化绑定

### 当前版本项目画像

到 `v0.7` 为止，这个项目已经形成了比较完整的三层价值：

- 业务层：区域占用检测、状态查询、事件记录、历史查询、管理员配置
- 工程层：认证授权、缓存、数据库、实时通信、前后端联动、脚本工具
- 质量层：自动化测试、压测、CI、状态隔离、回归可重复性

### 与上一阶段相比的变化重点

如果说上一阶段更强调“功能补齐”，那么 `v0.7` 更强调：

- 功能继续可用
- 配置来源统一
- 结构更可维护
- 测试更稳定
- 自动化集成更贴近真实工程环境

### 后续版本方向

- 继续补充部署文档与运维说明
- 把 Jenkins 与本地脚本进一步模块化
- 增加更细粒度的实时链路自动化验证
- 继续收敛剩余零散告警与历史兼容逻辑
